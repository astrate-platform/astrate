## Source 1 — Astrate codebase and docs (`origin/main` 89145e6)

Re-confirmed standing gaps against `origin/main` (grep-verified today):

- **`unset_not_allowed` still mis-mapped.** `errorname.go:62` maps
  `"unset_not_allowed"` → `"unexpected_value_type"`; the test at
  `errorname_test.go` pins the wrong value.
- **`decryption_error` / `malformed_capabilities_message` still absent** from
  `errorname.go` (neither name appears; unmapped reasons fall back to
  `interface_loading_failed` via `UpstreamErrorName`).
- **Malformed capabilities still rejects, not disconnects.**
  `capabilities.go:28` `handleCapabilities` rejects on decode/validate failure;
  `malformed_capabilities_message` is unmapped (`data.go:50` only defines
  `capabilities_payload_invalid`). Note the fix got cheaper: `DisconnectDevice`
  now exists (`broker.go:260`) — it just isn't called from the capabilities path.
- **Key agreement still ACL-denied.** `aclhook.go:65` deliberate-denial comment,
  asserted by `aclhook_test.go:53`. Zero key machinery behind it.
- **Encrypted endpoints still absent.** `git grep -i "dek|kek|cose"` over
  `origin/main -- internal/` matches only the `fakeKeys`/`fakeKeySource` JWT test
  doubles (`internal/auth/middleware_test.go:17`,
  `internal/appengine/stream/ws_test.go:39`).
- **emptyCache resend failure still has no trigger surface.**
  `handleEmptyCache` (`control.go:60-74`) wraps resend in `retryStore`; on
  permanent failure it returns without ack, firing no device_error trigger and
  never ending the session. `resendServerProperties` (`control.go:143-175`)
  skips unresolvable interfaces/paths/unrehydratable values loudly
  (`:152,157,162`). `resend_interface_properties_failed`/`empty_cache_error`
  remain mapped-but-never-emitted (`errorname.go:20-21`; only fixture uses in
  `events_test.go:45,108`).
- **BSON-null individual value still rejected**, pinned by
  `pkg/payload/payload_test.go:500` ("null v rejected").
- **Group-scoped triggers still compile-but-never-match.**
  `match.go:318,354` `noteUnsupported(c.GroupName != "", ...)`.
- **Unverified error names unchanged.** `docs/COMPATIBILITY.md:121-122`:
  `write_on_server_owned_interface` and `value_size_exceeded` "remain unverified
  guesses".
- **External-bus intake TODO still open** — `internal/store/store.go:135`
  (blocked on GitHub issue #10).

Exactly one sanctioned `// TODO` remains on main (the one above), consistent with
`docs/ROADMAP.md` §0.1 rule 3.

### Release branches — v1.3.3 and v1.4.0-rc.5

- `v1.3.3` is now actually tagged (`3e70d63f8`); its content (the
  `interface_loading_failed` vs `resend_interface_properties_failed` split) was
  already known from the 08-18 survey's CHANGELOG reading.
- `v1.4.0-rc.5` (`3484096d2`, 2026-08-20, cut from `release-1.4`, not an ancestor
  of master) adds one substantive fix over master:
  **`fdc6d29b8` — "fix(dup): Make object values only validate type on selected
  interface" (#2141)**. Upstream's DUP looked up object-aggregate mappings by
  endpoint across the whole endpoints table, so when two installed interfaces
  share an endpoint string, validation mixed mappings from the wrong interface;
  the fix filters extracted mappings to `m.interface_id == interface_id`
  (`data_updater/core/interface.ex:316-328`).
  **Not an Astrate gap:** Astrate validates object documents against
  `ci.ObjectLeaves` of the selected compiled interface only
  (`internal/engine/data.go:254`, leaves built per-interface at compile time) —
  it already behaves like post-fix upstream by construction. Worth one bench
  note: if the Legion's self-hosted upstream is rebuilt from a released version,
  rc.5 now includes this fix while master does not.
- The remaining rc.5 delta is release prep and a version-string forward-port
  (`4141a2ae4`: CHANGELOG/README/mix.exs version bumps only).
