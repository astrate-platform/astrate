## Source 3 — upstream `astarte-platform` (`85c05c67`, moved 2026-08-05)

`git log 5047681..85c05c67c` is exactly two commits. Neither touches `doc/` and
neither adds a CHANGELOG entry (still `Unreleased` empty, still tagged
1.4.0-rc.2).

### `b61a3ed33` — chore(DUP): Refactor encrypted endpoints (#2112)

"Update encrypted interfaces to support parameters." Production-code changes only
in the data-updater plant and appengine:

- `apps/astarte_data_updater_plant/.../core/data_handler.ex` — the set of
  `encrypted_endpoints` passed to `maybe_encrypt_value` is now filtered by the
  **current** interface (`&1.interface_id == context.interface_id`, previously all
  encrypted mappings across every interface in introspection), and the encryption
  context path is the **mapping's endpoint** (`mapping.endpoint`) rather than the
  received message `path`. This is what lets an encrypted mapping live on a
  parametrized endpoint such as `/%{some_param}/encryptedValue`.
- `apps/astarte_appengine_api/.../device/device.ex` — dropped a TO-DO noting
  Astarte Secrets could not generate a DEK without first generating a KEK (the
  generator path no longer needs that caveat).
- Everything else is tests (data_handler_test, support cases/helpers) adding a
  parametrized-encrypted-mapping fixture.

Wire-visible consequence for parity: when Astrate implements encrypted endpoints,
the encryption decision must be per-interface and endpoint-parameter-aware — an
encrypted mapping on `/foo/%{param}/bar` is encrypted only for that interface, and
the endpoint used as the encryption context is the mapping endpoint, not the
inbound path. This is an update to the already-tracked `encrypted-endpoints`
candidate, not a new gap.

### `85c05c67c` — refactor(generators)!: nuke to_changes + use adapters

A breaking refactor of upstream's **test tooling** — 169 files, almost all in
`libs/astarte_adapters/`, `libs/astarte_test_suite/`, `tools/astarte_e2e/` and
`*/test/support/`. It standardises the generator function names for `import`,
removes the `to_changes` functions, and moves test-suite helpers onto
`astarte_adapters`. It changes **zero** files under `apps/*/lib` (the only app
prod-code delta since `5047681` is `b61a3ed33`'s two files).

**Not a parity gap.** Astrate is a Go reimplementation with its own conformance
harness (`test/conformance/`); it does not reuse upstream's Elixir generators, so
removing `to_changes` upstream has nothing to map onto here. Checked and
dismissed — recorded only so the reader knows it was considered.

### Everything else upstream

Unchanged since `5047681`: key-agreement handshake, capabilities
force-disconnect + persistence, error-name inventory, protocol/trigger/interface
docs, standard interfaces. The 08-01 survey's §3 remains accurate; nothing to
re-derive.

## Source 4 — parity gaps (updated topology)

No gap closed, no new gap opened. The only topology change is a *refinement of an
open gap*:

| Area | Upstream behaviour | Astrate status | Reference |
|---|---|---|---|
| **Encrypted endpoints — now with params** | Encrypted mappings can live on parametrized endpoints; encryption scope is per-interface (filtered by `interface_id`); context path is the mapping endpoint | Entire subsystem absent (`dek\|kek\|cose` matches are false positives) | `b61a3ed33`; `data_handler.ex`; 08-01 survey |
| **Key agreement protocol** | CBOR handshake on `control/keyAgreement/0..4`; shared secret persisted, encrypted at rest | Not implemented; ACL deny + comment | `aclhook.go:65`; `aclhook_test.go:53` |
| **Capabilities: malformed handling** | Force-disconnect + `error_name: "malformed_capabilities_message"` | `e.reject` fires device_error, keeps connection, falls back to `interface_loading_failed` | `capabilities.go` `handleCapabilities`; `errorname.go` |
| **Capabilities: persistence** | DB-persisted per device | In-memory, session-scoped | 08-01 survey §4 |
| **`unset_not_allowed` error_name** | Emitted literally by upstream | Mapped to `unexpected_value_type` | `errorname.go:62` |
| **Group WATCH authz paths** | `groups/<name>/<interface><match_path>`, `groups/<name>` | Not measured (no group in realm); #17 | `COMPATIBILITY.md` deviation 1 |
| **`write_on_server_owned_interface` / `value_size_exceeded` error_names** | Emitted by upstream; threshold unclear for size | Mapped but unverified; #18/#19 | `COMPATIBILITY.md` deviation 1 |
| **Dormant data trigger types / group-scoped triggers** | Evaluated upstream | Accepted, never evaluated; #20 / tied to #17 | `match.go` |

The largest open subsystem is still key-agreement + encrypted-endpoints; the
upstream refactor only tells Astrate how that subsystem has grown since the
candidate was written (parameters support), it does not shrink it.
