## What moved: upstream `ac04ca95..de1aaa73` — key agreement is now a *documented, implemented* protocol

Five commits, four irrelevant and one material:

- `7d6c073`, `de1aaa7` — `astarte_test_suite` Conn/AuthConn fixtures (upstream's internal
  test lib; not wire-visible).
- `bf03265`, `6b4a896` — CI (release-please, workflows on release branches only).
- **`d084308` "docs: add encrypted endpoints key agreement (#2067)"** — the material one.
  It adds `doc/pages/architecture/082-key_agreement_protocol.md` (267 lines, the full wire
  protocol) and rewrites the Key Agreement section of `080-mqtt-v1-protocol.md`.

Consequences for the standing keyAgreement residue (candidate 1):

1. **The sentence Astrate's ACL comment leans on is gone.** The old doc carried, verbatim,
   both "reserved and routed correctly, but the handshake protocol is not yet implemented"
   and "accepted and acknowledged by Astarte, but no response is sent until the feature is
   fully implemented". The new 080 section says instead: devices and Astarte "establish a
   shared symmetric key"; the protocol is defined in 082. The implementation-status note in
   082 reads: "The handshake described on this page ... is implemented on the Astarte side
   (`astarte_data_updater_plant`). Device-side usage of the derived session key ... may
   still evolve." So the doc *and* the code (already instrumented at `ac04ca95`) now agree
   the handshake exists. `aclhook.go:66-69`'s "matches upstream's own status" conclusion is
   stale against both halves.
2. **The topic is now a formally-specified family.** 082's MQTT-topics table:
   `control/keyAgreement/0` InitExchange (device), `/1` ExchangeResp (Astarte), `/2`
   SecretHash (device), `/3` HashOk (Astarte), `/4` ExchangeFailed (Astarte), all QoS 2
   (the 080 topic table row moved from a single `control/keyAgreement` QoS 1 to
   `control/keyAgreement/<message id>` QoS 2). Message bodies are CBOR arrays (CDDL given);
   `InitExchange` carries `seq_num`, `alg` (0 = `ECDH_P256-HKDF_SHA256-AES_256_GCM`),
   a CBOR-wrapped COSE_Key pubkey, and a 32-byte `HkdfSalt`. Key is session-scoped, never
   reused after reconnect/clean-reset. Encrypted payloads are AES-256-GCM whole-document
   ciphertext; on "no key established yet" Astarte logs and **discards** the message
   (recoverable condition, no disconnect).
3. Reference for `ExchangeFailed` `error_code`s (0 internal, 1 invalid argument, 2 hash
   mismatch, 3 unprocessable entity) — useful if Astrate ever maps these to device-visible
   error names.
