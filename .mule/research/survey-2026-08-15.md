## Source 1 — Astrate codebase and docs (`main` 89145e6, unchanged)

No new commits since the 08-13 survey, so the Source-1 picture is unchanged.
Re-confirmed the standing greps against `origin/main`:

- **Encrypted endpoints still absent.** `git grep -i "dek\|kek\|cose"` over
  `internal/` matches only the `fakeKeys`/`fakeKeySource` JWT test doubles
  (`internal/auth/middleware_test.go:17-20`,
  `internal/appengine/stream/ws_test.go:39-42`).
- **Key agreement still ACL-only.** `internal/broker/aclhook.go:65` carries the
  deliberate-denial comment ("control/keyAgreement ... deliberately
  unsupported", matching upstream's own "reserved and routed" status);
  `aclhook_test.go:53` asserts the denial.
- **Malformed-capabilities handling still rejects, not disconnects.**
  `internal/engine/capabilities.go:28` `handleCapabilities` calls `e.reject` on
  both decode and validate failure (lines 31 and 36); `malformed_capabilities_message`
  is absent (only `capabilities_payload_invalid`, `internal/engine/data.go:50`).
- **`unset_not_allowed` still mis-mapped.** `errorname.go:62` maps
  `"unset_not_allowed"` → `"unexpected_value_type"`; the mapping test
  `errorname_test.go:30` pins the wrong value.
- **emptyCache resend failure emits no device_error trigger.** `handleEmptyCache`
  (`internal/engine/control.go:57`) and `resendServerProperties`
  (`control.go:143`) have no failure surface; `resend_interface_properties_failed`/
  `empty_cache_error` remain mapped (`errorname.go:20-21`) but never emitted —
  the only uses are fixtures (`events_test.go:45,108`).
- **BSON-null individual value still rejected.** `decodeBSONValue`
  (`pkg/payload/bson.go:60`) has no `bson.TypeNull` case, and
  `pkg/payload/payload_test.go:499-503` asserts "null v rejected" with
  `ReasonTypeMismatch` — the divergence from upstream `4789d047` stays pinned by
  an explicit test.

## Source 3 — upstream `astarte-platform` (`f2d53e1`, moved 08-13/08-14)

`git log 684da75..f2d53e1` is 4 commits, all landed by the same author
(Francesco Noacco). Grouped by relevance:

### Build/tooling — Elixir 1.20 / OTP 28 (#2071)

`0809af194` moves the toolchain `elixir 1.15.7-otp-26` / `erlang 26.1` →
`elixir 1.20.2-otp-28` / `erlang 28.5` (`.tool-versions`), bumps the Docker
builder/runtime base images to Debian trixie, and fixes the 125 files the
compiler surfaced. The source changes are all OTP-28/1.20 compat, none
wire-visible:

- struct-type pins on function heads (`%State{}` on `device.ex:354`
  `set_device_disconnected`, `interface.ex:43` `maybe_handle_cache_miss`,
  `time_based_actions.ex`), the `%{opts | ...}` map-update form
  (`device.ex:1395` in appengine), removed unused `require Logger`/aliases,
  `health.ex` `vernemq_health` made public with `@doc false` to satisfy the
  private-call rule, and a GenServer-callback reorder in the e2e tool.
- The one non-trivial diff touches **the encrypted-write path**:
  `data_handler.ex:220` `maybe_encrypt_value(:object, ...)` loses its
  `case encrypted_endpoints != []` guard for a bare `with`, with a
  `# SAFETY: empty encrypted_endpoints is matches a a clause above` comment —
  confirmed behaviour-neutral: the preceding clause at line 194
  `maybe_encrypt_value(_, _, value, [], _)` still short-circuits the empty
  case, and the individual-value clause is untouched. No change to the
  encryption subsystem; the `encrypted-endpoints` candidate stands exactly as
  written.
- Not a parity concern for Astrate (Go), but worth one line for the bench: if
  the Legion's self-hosted upstream is ever rebuilt from these images it runs
  Elixir 1.20 / OTP 28 / Debian trixie.

### Infra — vmq_plugin tests, nix, pairing dep

- `2c3239c8a` (#2134) — vmq_plugin test-only: a test file was renamed
  (`astarte_vmq_plugin_test_v2.exs` → `astarte_vmq_plugin_v2_test.exs`) so it
  actually runs, the helper config re-init and amqp helper fixed. The plugin is
  the VerneMQ broker glue Astrate replaces with its own embedded broker
  (`internal/broker/`); test-only changes there are no-gap.
- `4354979c5` (#2136) — `flake.nix` devshell tooling only (typos/dprint/committed).
- `f2d53e1ff` (#2137) — `apps/astarte_pairing` mix.exs/lock only (cfxxl pinned

No CHANGELOG entry (`## Unreleased` is empty), no new tag (newest remains

## Source 4 — parity gaps (updated topology)

**No rows added or removed.** The delta is toolchain/build consolidation with no
wire-visible change; the one encryption-adjacent diff (`data_handler.ex`) was
verified behaviour-neutral (Source 3). The standing topology from 08-13 carries
over unchanged:

| Area | Upstream behaviour | Astrate status | Reference |
|---|---|---|---|
| **key agreement** | Full ECDH/X25519 CBOR handshake, shared-secret persisted + encrypted at rest, gates payload decryption | Topic ACL-denied (`aclhook.go:65`); zero key machinery | `080-mqtt-v1-protocol.md:172-176` |
| **encrypted endpoints** | DEK/KEK at-rest wrap + COSE Encrypt0 transport both directions, parameter-aware | Absent (no DEK/KEK/COSE in `internal/`) | `astarte_secrets`; `data_handler.ex` `maybe_encrypt_value` |
| **emptyCache resend-failure triggers** | On `control/emptyCache` resend failure, device_error trigger with distinct name + clean-session disconnect | No failure surface: retries/acks/skips, never triggers, never disconnects | `d8592091`; `control.go:57-74,143-167` |
| **malformed capabilities** | Force-disconnect + `malformed_capabilities_message` | Rejects, keeps connection, wrong error_name | `capabilities.go:28`; `errorname.go` |
| **`unset_not_allowed`** | Emits literal `unset_not_allowed` | Mapped to `unexpected_value_type` | `errorname.go:62` |
| **BSON-null value** | `nil` individual value passes validation | Rejected `ReasonTypeMismatch` (pinned by `payload_test.go:499-503`); SDKs likely never send it (unverified) | `4789d047`; `bson.go` |

The largest open subsystem is still key-agreement + encrypted-endpoints
(carried). No new candidate emerged from this delta.
