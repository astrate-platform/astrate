### key-agreement-protocol
Title: Handle the `<realm>/<device_id>/control/keyAgreement` CBOR topic
Scope: mule-spec
Body:
Carried forward (re-grep-confirmed against `origin/main`: only the ACL deny
comment `internal/broker/aclhook.go:65` and its test `aclhook_test.go:53`; zero
key machinery anywhere in `internal/`). Upstream implements a 5-message CBOR
handshake over `keyAgreement/0`–`/4` (`InitExchange`, `ExchangeResp`,
`SecretHash`, `HashOk`, `ExchangeFailed`), X25519 (suite 1, default) and ECDH
P-256 (suite 0), a 32-byte AES-GCM key derived via HKDF and persisted in
`devices.shared_secret` (encrypted at rest with the realm KEK), with key status
gating payload decryption — making this the precondition for the COSE Encrypt0
data path below. Fix: (a) allow the topic in the broker ACL for the device's own
base, (b) decode the 5 CBOR message types, (c) implement the state machine, (d)
derive and persist the shared secret, (e) emit the upstream error names on
failure (`key_agreement_error`, `key_agreement_transition_error`,
`secret_hash_error`, `hash_ok_error`, `exchange_failed_error`). Verification: a
T3 handshake test and an invalid-InitExchange test asserting `key_agreement_error`.
Prerequisite for `encrypted-endpoints`.

### encrypted-endpoints
Title: Implement encrypted endpoints (DEK/KEK at-rest encryption, COSE Encrypt0 transport both directions, parameter-aware)
Scope: mule-spec
Body:
Carried forward (re-grep-confirmed: `git grep -i "dek|kek|cose" origin/main --
internal/` matches only the `fakeKeys`/`KeySource` JWT test doubles). Upstream
has two encryption layers for mappings with `encrypted: true`: (1) at-rest
DEK/KEK wrapping via Astarte Secrets (`encryptedblob_value`/`encrypted_dek`
columns, per-device shared secret encrypted under the realm KEK); (2) **COSE
Encrypt0** transport using the key-agreement shared secret on both directions —
appengine read path encrypts (`device.ex:311`), DUP write path decrypts before
BSON decoding (`maybe_decrypt_payload`). COSE Encrypt0 = 12-byte random IV +
AES-GCM ciphertext, alg from the handshake symmetric key, plaintext is the BSON
payload; if any mapping of the interface is encrypted, the whole payload is
encrypted; both sides use the mapping's endpoint (parameter-substituted) as
encryption context. Failure modes: write side `key_agreement_error` /
`decryption_error`, read side `device_not_ready_for_encryption`. Fix: (a)
encrypted-value columns, (b) secrets library for DEK wrap + shared-secret
encryption, (c) COSE Encrypt0 with mapping-endpoint context, (d) encrypt on
write / decrypt before BSON decode, (e) decrypt on read. Verification: T3 test
with an encrypted endpoint incl. a parametrized path, byte-identical COSE
round-trip fixture, failure modes asserting the named errors. Follows
`key-agreement-protocol`.

### empty-cache-error-triggers
Title: Fire device_error triggers on `control/emptyCache` resend failure, matching upstream's error_name split
Scope: mule-spec
Body:
Carried forward (re-grep-confirmed against `origin/main`: `handleEmptyCache`
`internal/engine/control.go:60-74` wraps resend in `retryStore` and on permanent
failure returns without ack — no device_error trigger, no session end;
`resendServerProperties` `control.go:143-175` skips unresolvable interfaces,
unmatched paths, unrehydratable values loudly with `continue`;
`resend_interface_properties_failed`/`empty_cache_error` stay mapped-but-never-
emitted, `errorname.go:20-21`, only fixture uses at `events_test.go:45,108`).
Upstream fires a device_error with a distinct name per failure class and ends
the session: `interface_loading_failed` on interface load failure,
`resend_interface_properties_failed` when sending fails, `empty_cache_error`
(reason in `extra_error_metadata`) otherwise. Design decision still required:
Astrate's skip-loudly behaviour is deliberate robustness and conflicts with
upstream's fail+disconnect — adopt upstream semantics, diverge with a documented
COMPATIBILITY.md note, or hybrid (skip quietly per row, trigger only on total
failure). Verification: a T2/T3 test asserting a device_error trigger with the
correct error_name fires on an emptyCache resend failure.
