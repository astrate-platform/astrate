Upstream Astarte fires a `device_registered` device trigger when a device is registered via
the Pairing API (`060-triggers.md:109`). Astrate's pairing service
(`internal/pairing/service.go`) never emits a trigger event on registration — confirmed by
`grep -rn "device_registered" internal/` returning nothing. Any upstream trigger with
`on: device_registered` installs successfully on Astrate but never fires.

**Fix**: after successful registration in the pairing service, emit a `DeviceRegisteredEvent`
on the trigger bus, the same path `device_connected` already uses.

**Verification**: add a test in `internal/pairing/service_test.go` that registers a device and
asserts the trigger bus receives a `DeviceRegisteredEvent` with the correct device ID and
realm; the test must fail without the change.

Found by a cross-project survey comparing Astrate against upstream astarte-platform
(`.mule/research/survey-2026-07-27.md`, source 1/4).

+// HandleDeviceRegistered is called by the pairing service after a successful
+// device registration. It fires device_registered triggers and publishes the
+// event on the live bus — the same path device_connected already uses.
+func (e *Engine) HandleDeviceRegistered(realmName string, hwID string, at time.Time) {
+	rs := e.schemas.realm(realmName)
+	if rs == nil {
+		return
+	}
+	id, err := deviceid.Parse(hwID)
+	if err != nil {
+		return
+	}
+	e.fireDevice(rs, id, at,
+		triggers.DeviceEvent{DeviceID: hwID, On: triggers.OnDeviceRegistered},
+		triggers.NewDeviceRegisteredEvent())
+	e.bus.Publish(stream.Event{
+		Kind: stream.KindDeviceRegistered, Realm: rs.name, DeviceID: hwID, Timestamp: at,
+	})
+}
