# Code review — internal/testutil — 2026-10-08

Rotation check: `container-2026-10-02` recorded that every `internal/` and `pkg/`
package has a review file *except* `internal/testutil`, which it dismissed in
passing as "test helpers, no logic worth proposing on" without reading it. That
dismissal is why this pass exists: the package has no review of its own, it is
imported by 23 files across broker/engine/appengine/store tests plus the

either does or does not assert. It is also small enough to read whole, which is

## What I found (worth proposing)

### 1. `WaitForMessage` can only ever return the *earliest* match, and in-tree that makes a resync assertion vacuous

`WaitForMessage` (astartedevice.go:149-162) scans `d.Messages()` — the whole
capture buffer — from index 0 on every poll and returns the first message
satisfying `pred`. There is no "since" cursor, so a *second* wait for a topic
that already has a message returns that old message immediately.

That is not hypothetical: `testE2EEmptyCache`
(internal/engine/engine_e2e_test.go:353-380) does exactly this. It captures the
retained set at :362, calls `dev.EmptyCache(t)` at :364, then at :367 waits
*again* for the same `propTopic` with the comment "the resync re-publishes the
property value on its data topic" and asserts at :368-369 that the payload
decodes to `int32(42)`. The wait returns the pre-`EmptyCache` message — which
carries the same value 42 — so the assertion passes even if the resync
re-publish never happens. Payload filtering cannot rescue it either: the resent
value is byte-identical to the retained one. The e2e suite's only
emptyCache-resend check is a tautology today.

The helper needs a cursor (`Mark() int` + a `From(start, ...)` wait) and the
paho capture handler must move out of the `ConnectAstarteDevice` closure into an
injectable method, or the new logic cannot be tested without a broker.

### 2. The producer/properties control frame is asserted nowhere on the default gate, and the helper's inflate is unbounded

`DeflateControlList` / `InflateControlList` (astartedevice.go:181-216) carry the
4-byte big-endian uncompressed-length prefix + zlib framing that
`SendProducerProperties` (:135-138) puts on the wire. They have **zero tests**,
and every caller of the helpers sits behind a build tag (`e2e`,
`integration && e2e`, or the conformance runners), so on the Pi's container-free
gate nothing asserts the framing. The parser side *is* pinned —
`internal/engine/control_test.go:89-130` plus a CPython-produced golden frame —
but the producer side only meets it under `-tags e2e`.

Second, while reading it: `InflateControlList` does `io.ReadAll(zr)`
(astartedevice.go:205) with no ceiling and no declared-size check beyond the
post-hoc `len(plain) != declared` compare at :209. The engine's own
`inflateProperties` bounds the identical stream with
`io.LimitReader(zr, int64(declared)+1)` and a `maxControlInflated = 1<<20`
ceiling (internal/engine/control.go:30, 301, 305-315). A frame whose header
lies about a huge size makes the helper allocate all of it before failing — and
the payload it would be parsing comes from the code under test, i.e. exactly the
case where "the test harness exploded" beats "the test failed". Bounding it the
way the engine does is mechanical, and the truncated byte count in the mismatch
error pins the bound in a way that fails today.

### 3. The introspection *producer* half is never checked off-tag

`testutil.Introspection` (:93-105) renders the `;`-separated `name:major:minor`
string the device publishes. All six of its callers are behind `e2e`,
`integration && e2e`, or `test/conformance`, while the consumer
(`parseIntrospection`, internal/engine/introspection.go:99-127) is tested only
against hand-written literals in `internal/engine/introspection_test.go:17-71`.
So no test on the default gate checks that the string the harness builds is the
one the engine accepts, or that the documented "deterministic (sorted)
ordering" (:91-92) holds — a regression that emitted `name:major` (dropping
minor), sorted nothing, or appended a trailing `;` would break only on the
Legion, in tests that then fail for a reason far from the cause.

## What I decided NOT to propose, and why

- **`InflateControlList` has no in-tree caller at all.** It is the documented
  inverse of `DeflateControlList`, yet `engine_e2e_test.go:423-430` reimplements
  it as `controlEntries` and `test/security/security_test.go` builds its own
  frame. Consolidating the duplicate would touch e2e-tagged files, which the Pi
  cannot compile or run, so the change could not be verified in one task; and
  deleting the helper is wrong if proposal 2 is going to test it. Recorded here
  so the next run does not re-derive it — a follow-up line can retire
  `controlEntries` in favour of it once the e2e suite is reachable.
- **`Golden`'s failure output prints raw bytes with `%s`** (golden.go:46-47), so
  a binary fixture diff is unreadable terminal noise. `firstDiff` gives the
  offset and the lengths give the shape; `%q` would be nicer but this is
  cosmetics on an already-correct failure path, and `golden_test.go` pins the
  behaviour that matters. Not worth a task.
- **`MQTTTryConnect` does not `Disconnect` on the `token.Error() != nil` branch**
  (mqttclient.go:126-128) — only the timeout branch (:123-124) does. The
  connection has already been refused at that point and every caller either
  fails the test or asserts the refusal, so nothing outlives the test binary.
- **`WaitForTopic` requires `len(m.Payload) > 0`** (:168), which makes it unable
  to wait for a property-unset retained clear (the empty payload
  `ServerMessage.Payload` documents at :49). No caller needs that today — a wait
  for an empty payload can still be written with `WaitForMessage` — so there is
  no in-tree defect, only an unused affordance.
- **Package doc drift**: the doc comment on `pg.go:1-4` describes the package as
  "the T2 TimescaleDB container helper and the golden-file comparison helper",
  omitting the MQTT device harness that most of its callers actually import.
  One sentence; the linter does not own prose and this does not change
  behaviour. Not a task.
- **`ServerTLSCert` uses `SerialNumber: big.NewInt(1)` and a 24h `NotAfter`**
  (mqttclient.go:36-37) — fine for a self-signed test cert; every consumer
  generates a fresh one per test.
- **`openPool`'s ping loop** (pg.go:93-105) has a `readyTimeout` deadline and
  bounded 5s ping contexts; `TimescaleImage` is pinned against
  docker-compose.yml with the load-bearing `-ha` comment. Nothing to propose —
  and `pg_test.go` is `integration`, so this file is Legion-only by construction.
