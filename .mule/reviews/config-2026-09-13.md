# Code review: internal/config — 2026-09-13

## What I read

`internal/config/config.go` (411 lines) in full, `internal/config/config_test.go` (407 lines) in full.
Traced callers of every unvalidated field to confirm downstream guard status via targeted grep.

## Findings

### 1. `ASTRATE_ENGINE_SHARDS` parse error silently ignored (config.go:258-262) — category 1

```go
if v, ok := os.LookupEnv("ASTRATE_ENGINE_SHARDS"); ok {
    if n, err := strconv.Atoi(v); err == nil {
        cfg.Engine.Shards = n
    }
}
```

A malformed value (e.g. `ASTRATE_ENGINE_SHARDS=banana`) is silently dropped: the parse
error is discarded and the TOML/default shard count stays in force. The operator thinks
shards are 8; they are actually 16.

Contrast with the immediately adjacent `ASTRATE_HOUSEKEEPING_REALM_DELETION_DISABLED`
(lines 288-297) which is fail-loud: "banana" returns an error and refuses to load. The
two are the same shape — env overrides a typed config field — but have opposite
failure policies.

`router.NewRouter` (internal/engine/router.go:162) does catch *negative* values as a
separate guard, but garbage strings like "banana" bypass `Atoi` entirely (the `if err == nil`
arm is skipped) and silently carry the prior value forward.

Proposed: return the parse error, matching the fail-loud convention. A test asserting
that `ASTRATE_ENGINE_SHARDS=banana` causes Load to fail is the proof; the test fails
without the fix because garbage currently produces nil error.

### 2. `ASTRATE_MQTT_INSECURE_DEV_MODE` parse error silently ignored (config.go:255-257) — category 1

```go
if v, ok := os.LookupEnv("ASTRATE_MQTT_INSECURE_DEV_MODE"); ok {
    cfg.MQTT.InsecureDevMode, _ = strconv.ParseBool(v)
}
```

Same swallow, different consequence. `strconv.ParseBool` accepts only a small set of
strings ("1","t","T","TRUE",...); anything else is an error discarded as `_`. The field
becomes `false`, silently re-enabling TLS cert requirements.

If the TOML already had `insecure_dev_mode = true`, this silently flips it to false,
which makes `validate` reject the config because TLS cert files are empty — so the
error surfaces indirectly via a misleading "tls_cert_file required" message rather than
"astra_e_MQTT_INSECURE_DEV_MODE has invalid value". An operator setting the env to
"y" or "yes" (common truthy spellings that ParseBool rejects) gets the same broken
outcome.

Proposed: return the parse error. A test asserting `ASTRATE_MQTT_INSECURE_DEV_MODE=yes`
causes Load to fail is the proof.

### 3. Zero test coverage for `HousekeepingKeys()` and `RealmJWTPublicKey()` (config.go:383-411) — category 2

Both file-reading helpers are completely untested:

- `HousekeepingKeys()` — copies inline keys, reads referenced files, trims whitespace,
  returns file-not-found errors with the path in the message.
- `RealmJWTPublicKey()` — prefers inline over file, reads file if inline is empty,
  trims whitespace, returns file-not-found errors.

Rules with zero test assertions are silent rot vectors. A trim change, a changed error
message, or a file-read path that silently swallows `os.ErrNotExist` would pass every
existing test. These are simple to cover: `t.TempDir()` + `os.WriteFile` for the happy
paths; non-existent paths for the error branches; verify TrimSpace strips surrounding
newlines (PEM blocks are often pasted with trailing newlines).

## What I decided not to propose

- **Negative pairing rates/bursts**: `NewLimiter` (internal/pairing/ratelimit.go:35-40)
  already clamps negative rates to 1/60 and non-positive bursts to 1. The downstream is
  guarded; validation would be belt-and-suspenders.

- **Negative engine fields**: `router.NewRouter` (internal/engine/router.go:162) returns
  error for `ShardQueue <= 0`, `BatchMaxRows <= 0`, `MaxPayloadBytes <= 0`. Guarded in a
  different layer; not a gap.

- **CORS ftp:// scheme passing validation** (config.go:318-326): the CORS validator
  checks `u.Scheme != ""` but does not whitelist http/https. Harmless — browsers never
  send an ftp:// Origin header, so such an entry never matches. No downstream impact.

- **Duration.MarshalText test**: one-liner implementation, no rule worth asserting.
- **Log level/format env override tests**: trivial string copies, already proven by the
  DSN/shards env mechanism in TestDefaultsAndPrecedence.
