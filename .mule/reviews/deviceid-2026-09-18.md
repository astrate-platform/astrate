## What I found

The package is compact, idiomatic, and unusually well pinned:

- Encodings cross-checked against a real `astartectl` v1.0.1 binary and CPython
  `uuid.uuid5` (deviceid_test.go:9-31, 73-87) — not against a reading of the
  code. Both encodings and the UUIDv5 derivation round-trip byte-identically.
- Every rejection class of `Parse` is asserted (length, padding, standard
  alphabet, whitespace, non-ASCII, non-canonical trailing bits) and every
  failure path wraps `ErrInvalid` so `errors.Is` classification is tested.
- `Random()` is pinned to UUIDv4 shape (version nibble + variant bits) and to
  non-collision over a sample.
- `FuzzParse` enforces the strongest possible invariant (accepted input must
  round-trip to itself), so any accidental relaxation of the strict encoding
  is caught.
- `FromUUID` accepts uppercase and always emits lowercase canonical; braces,
  URN prefix, wrong separators, non-hex all rejected and tested.

No unchecked errors, no nil paths, no unbounded growth, no concurrency — none
of the "wrong or unguarded behaviour" categories apply.

### One suspected asymmetry: the strict-mode claim of upstream parity

`deviceid.go:34-37` uses `base64.RawURLEncoding.Strict()` and justifies it
with "Upstream Astarte decodes device IDs the same way (Elixir
`Base.url_decode64!(padding: false)`)", and the rejection of
`"AAAAAAAAAAAAAAAAAAAAAB"` (trailing unused bits set) is asserted at
deviceid_test.go:176-177.

But the two decoders are **not** the same on that exact point. Go's
`Strict()` errors when the unused bits of the final (22nd) character are
nonzero. Elixir's `Base.url_decode64!` never inspects those bits — it decodes
the 128 payload bits and discards the rest. So Astrate is *stricter* than
upstream on the same wire form: a device ID with garbage in the low 4 bits of
the 22nd segment is accepted by upstream Astarte (MQTT topics, REST paths,
the pairing register op) but rejected by `deviceid.Parse` here — a plausible
wire-compat break in a package whose entire stated purpose is wire parity
(deviceid.go:1-10).

I have *not* run Elixir to confirm — this box is the Pi, no Docker, no
Erlang/Elixir (checked). Per MULE.md "verifying against things you do not
control", the measurement comes first: proposed as a `[legion]` probe task
against the running upstream stack. The relax-vs-strict decision is Giulio's
and is written to `.mule/for-giulio.md` pending the probe.

## Decided not to propose, and why

- **`FuzzFromUUID`** (parser invariant "accepted → `strings.ToLower(input)`
  round-trips"): value marginal. `TestRoundTripRandom` already drives
  `FromUUID` over 1000 uniformly random byte distributions and
  `TestFromUUIDRejections` pins the acceptance surface; a fuzz over a
  fixed-shape parser MostlyGeneratesRejections and would duplicate existing
  coverage for the price of corpus maintenance. Next run should not re-raise.
- **The unreachable `n != len(id)` guard** (deviceid.go:55-58): deliberately
  kept, documented, not worth a task.
- **`MarshalText`/`UnmarshalText` on `ID`**: a feature, not a gap — every
  caller persists/transmits the 22-char `String()` form, not the `ID` struct,
  so JSON of `ID` is not on any wire. Design decision if wanted → Giulio, not
  the queue. Not escalated: too weak to spend a for-giulio line on it.
- **`isExtendedDeviceID` / trigger `device_id` validation**
  (match.go:488-519): caller-side, correctly interleaved with `Parse`'s
  failure (long-form ids keep upstream's distinct "128 bits" message and the
  case is pinned at match_test.go:386), and it lives in engine-triggers —
  engine's slice was already reviewed 2026-09-06.
- **The silent `return` on `Parse` failure in engine.go:382-385/418-421**:
  intentional drop of bad event-carried ids; the ids originate from pairing's
  already-validated registration path, so no user input reaches it
  unvalidated. Not proposing.
- **`Random()` error path**: `crypto/rand` failure is not injectable in a
  test; nothing to assert.

## Verdict

Small, well-tested package; finding one plausible (unverified) parity break
is a real result. No code written this run, no git touched.
