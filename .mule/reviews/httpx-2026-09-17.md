# Review — internal/httpx

Date: 2026-09-17
Reviewed files: cors.go (1–49), notfound.go (1–56), cors_test.go (1–113),
notfound_test.go (1–139), and the wiring in cmd/astrate/main.go:416-422
(NotFound wraps the mux, CORS wraps NotFound only when
`config.HTTP.CORSAllowedOrigins` is non-empty) plus the origin validation in
internal/config/config.go:327-333.

Two small, tightly-scoped middlewares; both are thin and both are unusually well
tested for their size. `NotFound`'s four-segment envelope (appengine /
realmmanagement → `DetailRouteNotFound`, pairing / housekeeping →
`DetailPageNotFound`, everything else keeps Go's plain-text 404) is pinned
verbatim including the Content-Type, the 405 method-mismatch replay, header
forwarding and a large-body passthrough, all backed by the upstream recording in
`test/conformance/upstream/rest-errors.json`. `CORS`'s wildcard vs allowed-list,
disallowed-origin passthrough, non-preflight OPTIONS and no-Origin cases are all
pinned too. One real gap found, in CORS.

## Finding 1: disallowed-origin pass-through in non-wildcard mode omits `Vary: Origin`

`cors.go:26-29` — when the origin list is specific (no `*`) and this request's
`Origin` is not in it, the middleware passes through completely unstamped:

```go
if origin == "" || (!wildcard && !allowed[origin]) {
    next.ServeHTTP(w, r)
    return
}
```

But in non-wildcard mode the response *does* vary on the `Origin` header:
an allowed origin gets `Access-Control-Allow-Origin: <origin>` + `Vary: Origin`
(stamped at cors.go:35-36), a disallowed one gets neither. RFC 9110 §12.5.5
requires the variation field on responses whose value depends on the request's
`Origin`; omitting it here lets a shared cache (nginx/varnish/Cloudflare in
front — nothing in Astrate forbids one) store, say, the disallowed-origin 404
variant and serve it to a later allowed-origin request that should have carried
`Access-Control-Allow-Origin`, silently breaking (or worse, for the reverse
direction, granting) the browser CORS decision. The `Vary` is stamped only after
the allowed-origin guard, so the pass-through branch never sees it.

The related rule is also only half-guarded: `TestCORSActualRequestStamped`
(cors_test.go:50-60) pins the `Access-Control-Allow-Origin` echo on the actual
(non-preflight) allowed-origin request but not `Vary: Origin`; that assertion
lives only in `TestCORSPreflight` (cors_test.go:42). The preflight path therefore
keeps line 36 honest, but a regression that dropped `Vary` from actual
non-preflight responses would pass the whole suite.

**Proposed task:** in non-wildcard mode, stamp `h.Add("Vary", "Origin")` for any
request that carries an `Origin` header, *including* the disallowed-origin
pass-through at cors.go:26-29; and assert `Vary: Origin` on the stamped actual
non-preflight response in `TestCORSActualRequestStamped` and on the unstamped
pass-through in `TestCORSDisallowedOriginPassesThroughUnstamped`. Both are
container-free, and the change is additive (a header) so it cannot break the
`NotFound` replay (which never overwrites an existing `Vary`).

## Not proposing

- **The `NotFound` envelope covers only four prefixes** (notfound.go:49-54):
  unmatched routes under `/flow/v1`, `/astrate/v1`, etc. keep today's
  plain-text 404, even though the middleware's stated purpose — client code that
  "would choke on" a text body (main.go:416-418) — applies to them too. This is
  documented as deliberate, grounded in the upstream recording (only four
  segments observed); extending it to Astrate-native prefixes would invent
  behaviour without a measurement. Noted, not proposed.
- **A `Vary: Origin` on the `origin == ""` branch**: requests with no `Origin`
  produce the same response regardless of any header, so no variation — correct
  as-is.
- **Wildcard mode with a mixed list (`["*", "http://x"]`)**: `*` wins and is
  correctly invariant, so no `Vary`; the specific origin in the list is
  unreachable. Not worth a test.
- **`replay()` header copy shares the recorder's slice array**
  (notfound.go:27-28): the outer handlers never append to a replayed key after
  the rewrite, and the CORS wrapper's `Header().Add("Vary", ...)` only touches
  keys the mux's 404/405 recorders do not set. No mutation risk.
- **Hardcoded preflight allow-lists** (cors.go:40-41): methods and headers are a
  fixed literal and never echo `Access-Control-Request-Method`/
  `Access-Control-Request-Headers`. The only methods/headers the surface uses
  today are covered; echoing a new header would be speculative.
- **`_ = astarteapi.WriteError` discarded** (notfound.go:46, 48): a 404 error
  envelope cannot fail to encode; matching the package's existing style.
- **`Access-Control-Max-Age: "600"` hardcoded**: a caching choice, not a bug.

Verdict: `NotFound` is clean; one CORS variation-marker gap (small, additive,
fully machine-checkable) proposed.
