## What I read in detail

I focused on the three seams where mochi's semantics meet Astrate's rules and a wrong guess would cost data or a security boundary: (a) the ACL cold-cache miss path in `OnACLCheck`, (b) `DisconnectDevice` on device deletion vs the persistent bbolt session, (c) the offline-delivery ACL. I verified mochi internals directly for the claims below rather than positing them.

## Findings

### 1. ACL-miss reload is structurally dead for the first second after connect — a legitimate QoS0 publish is silently dropped

**Where:** `internal/broker/aclhook.go:183-195` (`OnACLCheck` miss path), `authhook.go:184-197` (`refreshIfStale`), `authhook.go:404` (admit stamps `lastIntroLoad = now`).

When a device publishes to an interface its session's ownership map does not know, `OnACLCheck` calls `sess.refreshIfStale` and then *re-checks the same still-cold cache*:

```go
own, ok := sess.ownershipOf(iface)
if !ok { sess.refreshIfStale(...); own, ok = sess.ownershipOf(iface) }
```

`refreshIfStale` treats the debounce as satisfied only if `time.Since(lastIntroLoad) >= introspectionReloadDebounce` (authhook.go:186). But `admit` stamps `lastIntroLoad = time.Now()` at connect. So for the whole first second after connect, **every** ACL-miss reload is skipped — including the exact case the code is for: a device that introspects (engine persists the introspection, but `Broker.RefreshIntrospection` has not yet run) and immediately publishes data. `processPublish` (mochi server.go:867-873) silently drops a denied QoS0 publish (`return nil`); a denied QoS1 disconnects the device (v4) — a reconnect storm on the SDK boot hot path.

I verified the interleaving is reachable end-to-end at the T1 level (fake store + real TLS broker + bbolt, no Docker): the fake store clones the device row per `GetDevice`, so mutating the fixture's `Introspection`/`interfaces` after connect reproduces "persisted but not yet refreshed".

**Proposed task:** `broker-acl-coldstart-introspection-miss` — fix the miss path so that when the debounce skips the reload, it falls back to a synchronous store read for the unknown interface instead of denying the packet; and add the T1 test that connects with an empty-introspection store, adds the interface + introspection to the store after connect (forcing `lastIntroLoad` to a fresh stamp to de-flake), and asserts a QoS0 publish to that interface reaches the intake. The anti-flood property is preserved: the fallback is per unknown interface and the map is warm afterwards.

### 2. `DisconnectDevice` leaves a zombie persistent session — a re-registered device resurrects the deleted device's subscriptions and offline queue

**Where:** `internal/broker/broker.go:260-266` (`DisconnectDevice`), `sessionstore.go:500-523` (`dropClient` already exists but is only reached through expiry/takeover).

`DisconnectDevice` force-closes the live connection with `packets.ErrNotAuthorized`. I verified in mochi (server.go:485-491) that `expire` is derived from the client's Clean flag / session-expiry interval, **not** from the reason code: `DisconnectClient` → `cl.Stop` → read-loop exit → `OnDisconnect(cl, err, expire=false)` for a persistent-session device. That path skips `s.UnsubscribeClient` / `Clients.Delete` **and** skips `sessionStore.OnDisconnect`'s `dropClient`. The device's subscriptions and offline queue stay in the bbolt file, keyed by CN = `<realm>/<device_id>`.

The comment says deletion "kicks the session before wiping the rows" — but only the live connection and the DB rows go away; the persisted session survives. A later device registered with the same ID (plausible for programmatically-decided IDs, not just random UUIDs) inherits the deleted device's session (session_present=true, old subscriptions, whatever was queued).

**Proposed task:** `broker-disconnect-device-zombie-session` — on device deletion, also drop the persisted session records for the CN (wire the session store handle into `Broker` and call `dropClient` from `DisconnectDevice`), and add a T1 test: connect clean=false + subscribe, call `DisconnectDevice`, reconnect — assert `session_present` is false and the stale subscription is gone. (If the design intent is to mirror upstream's session-kept behaviour, the test documents that instead; but a stale session outliving the device that owns it is the surprising default.)

### 3. The offline-delivery ACL has no direct tests

**Where:** `internal/broker/aclhook.go:95-157` (`offlineACL`), `OnACLCheck` offline branch `aclhook.go:196-202`.

`TestCheckACLMatrix` exercises the pure `checkACL`; nothing tests the offline path — cache hit within TTL, TTL expiry triggering a reload, load failure caching as empty (deny), or that `OnACLCheck`'s offline branch (delivery to a session-present but disconnected device) consults `ownershipOf`. The rule "deliver a server-owned message to an offline device's persistent session only if the interface resolves server ownership" currently rots unasserted, and the store behind it is the fake, so T1-level (no Docker) coverage is achievable.

**Proposed task:** `broker-offline-acl-tests` — in `aclhook_test.go`, unit-test `offlineACL.ownershipOf` for the cache-hit, TTL-refresh, and load-failure-deny paths, plus a T1 `OnACLCheck` offline-delivery check.

### 4. Truncated doc comment on `OnConnect`'s Will-clearing

**Where:** `internal/broker/authhook.go:314`.

The comment opens mid-sentence — "of the Astarte MQTT v1 protocol, and mochi publishes them without a publish-side ACL check…" — with the first line missing. The behaviour (clearing `Properties.Will`) is correct per mochi ([MQTT-3.1.2-10] clears the will after CONNACK) and the security rationale (a retained LWT would escape the §3.2 matrix) matters enough to be fully documented.

**Proposed task:** `broker-onconnect-doc-comment` — restore the missing first line.

## Decided NOT to propose, and why

- **`Publisher.Publish` per-message expiry.** Checked mochi `processPublish` (server.go:889-891): `pk.Expiry` is computed from `Properties.MessageExpiryInterval` for inline publishes too, so the offline sweeper and the persist path see it. Not a bug; the e2e expiry test also proves it.
- **`offlineACL` cache-stampede.** The slot is claimed with a fresh `loadedAt` before the slow load, so concurrent deliveries share one load. Guarded as well as it needs to be.
- **`Close` quiesce dance.** Documented mochi race with a pinned-version workaround and a clean structure; reopening it is not tick-sized.
- **`normalizeInflightOrder` / Seq.** Correctly scoped per bucket (bbolt `NextSequence` is bucket-global) and already tested both at unit and e2e level.
- **`OnSessionEstablish` inflight pruning.** Fine-grained and covered by the restore-path tests; the expiry sweep at load handles the down-time case.
- **Defensive `register`/`dropClient` edge cases in the session store.** The T1 + e2e suites cover the real paths; adding more would be padding.
