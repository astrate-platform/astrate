# Field report — trickle run, astrate "trigger delivery policies", 2026-07-25

One architect (Opus), two supervisors (Sonnet), eight delegate rounds
(opencode/big-pickle), seven phases, nine signed commits, ~1350 net lines.
Everything below is measured from that run, not extrapolated.

## What the numbers say

| Phase | Rounds | Delegate seconds | Landed as written? |
| --- | --- | --- | --- |
| 01 policy compile | 1 | 175 | yes (after a `gofmt -w`) |
| 02 trigger policy field | 1 | 102 | yes, nothing touched |
| 03 executor strategy | 2 | 229 + 58 | no — see below |
| 04 ttl + capacity | 1 | 530 | yes (after a staticcheck nit) |
| 05 realm delegates validation | 1 | 92 | yes, nothing touched |
| 06 referential checks | 1 | ~180 | yes |
| 07 cache attaches policies | 1 | 265 | yes |

Supervisor token cost: **~153k** for phases 01–04, **~76k** for 05–07. The
second group was cheaper mostly because the architect did phase 06's landing
and its integration test personally, which moved cost up a tier rather than
removing it.

7 of 8 rounds landed correct on the first pass. **The delegate never once broke
the invariant that mattered** (the no-policy path staying byte-for-byte
identical) and never edited a pre-existing test to make its own work pass.
Tightly scoped phases work. The failure modes are elsewhere.

## The one real defect, and what it teaches

Phase 03 round 1 passed every test and was wrong. It computed a `Decision`
whose `Reason` explains why a delivery was retried or discarded, logged it on
three branches, and silently omitted it on the fourth — the ordinary
in-progress retry, which is the branch that fires most. The tests assert on
counters, not log output, so no test could have caught it.

Generalised: **the delegate implements the value and forgets the consumer.**
It will compute a thing the spec asked for and not wire it to the place the
spec said it was for, whenever no assertion binds the two. This is not a
capability limit — the fix, once named, was one line in 58 seconds.

Countermeasure, cheap and mechanical: whenever a phase exists for
observability, the spec must (a) name the log line verbatim and (b) require a
test that asserts on captured log output, not on a counter. `slog` into a
`bytes.Buffer` handler costs the delegate four lines.

## Failure taxonomy, ranked by token cost

1. **Environment, not models — by far the most expensive category this run.**
   Go was not installed on the host at all. `commit.gpgsign=true` with a gpg
   agent whose cache expires mid-run, hanging `git commit` for the full
   timeout with no prompt reaching the harness (hit twice). A Docker Desktop
   update that wiped running containers rather than restarting them. An
   opencode provider outage that I misdiagnosed as missing credentials,
   because `opencode auth list` legitimately reports 0 credentials for a
   zero-auth provider. Each of these burned architect tool calls and
   reasoning, which is the most expensive tier in the whole scheme.
2. **Mechanical lint/format residue — one per round, every round, without
   exception.** gofmt misalignment, an unused handler parameter, a
   staticcheck QF1006 loop shape. Always trivial, always caught by a tool,
   never once caught by the delegate itself.
3. **Structural residue after refactoring.** Phase 03 extracted one case out
   of a `switch` and left a single-case `switch` behind. Phase 04 called
   `d.Trigger.Policy()` twice in adjacent `if` statements. Phase 07 keyed a
   map on the compiled document's name where the referencing identity is the
   stored row's name. All three were architect cleanups. **The delegate does
   not tidy the shape of code it has just restructured.**
4. **Harness friction.** `trickle.sh land` is rejected by the permission
   system for subagents but works for the main session, which forced a
   round-trip per phase: supervisor drives, stops, architect lands and
   commits, architect messages supervisor to continue. That is three extra
   architect turns per phase.
5. **Supervisor process slips.** One ended its turn waiting on a background
   command, and background notifications do not reach an agent that is no
   longer in its turn — it looked like a report but was a silent stall. One
   ran `drop` against an explicit instruction (harmless, and it disclosed it).

## Proposed changes, ranked by expected token saved

### 1. `trickle.sh preflight` — the single highest-value addition

Before any delegation, check and report in one shot: the project's toolchain
actually runs (`go version` or equivalent), `opencode` resolves a model,
the test command exits cleanly on a pristine tree (**capture the baseline**),
the linter runs, Docker is up if the config needs it, and — if
`commit.gpgsign` is true — that a signature can be produced *right now*.

Category 1 was the most expensive thing in this run and is almost entirely
preventable by one command that fails loudly at minute zero instead of at
minute forty. The gpg check in particular: warm the agent before the run,
not between phases.

### 2. Fold the mechanical pass into the script, not into a model

After every round, before `diff` and `test`, run the formatter and the
linter's autofix. Category 2 happened on **every single round**, cost a
supervisor tool call and a paragraph of reasoning each time, and is
deterministic. No model should be spending tokens on `gofmt`.

### 3. Per-phase file allowlist enforced by the script

Every spec already names the files the phase may touch. Put them in a
machine-readable header and have the script reject a diff that strays, the
way `TRICKLE_NEVER` already works. That deletes an entire category of
supervisor reasoning ("did it touch anything it shouldn't?") and turns it
into an exit code.

### 4. `trickle.sh prove <name> <impl-file>` — verify the test fails without the fix

Twice in this run I stashed the implementation and re-ran the new test to
confirm it goes red: the shutdown-race test, and the referential-integrity
test. Both times it was informative, and once it was the only evidence that
an `integration`-tagged check worked at all, since the T1 gate could only
prove it compiled. A regression test never observed to fail is worth very
little. This is three git commands — it should be a subcommand, not a habit
the architect has to remember.

### 5. Template the boilerplate half of the phase spec

`## Constraints` and `## Acceptance criteria` were near-identical across all
seven specs — no new deps, no network, don't touch X, report don't fix,
here are the commands. Ship them as a template in the skill so the architect
writes only `## Context` and `## What to do`. The spec is where quality comes
from and must stay at the top tier; the surrounding furniture need not be
retyped seven times.

### 6. Fix the `land` permission, then let the supervisor commit

If the supervisor could land and commit, the architect's per-phase
involvement drops to reading a diff. The blocker is a permission rule, not a
design constraint. Commit *messages* should still come from the architect —
pre-writing all four for a group worked fine, with the standing rule that a
message which no longer describes the diff means stop and escalate rather
than reword. That rule never had to fire, but it is what made pre-writing
safe.

### 7. Two lines for the supervisor brief

- Never end your turn waiting on a background command; run in the foreground
  or poll inside your own turn.
- `Error: No provider available` is a transient outage, not a spec problem
  and not an auth problem. Wait, retry twice, then stop. Log it as infra so
  the rounds column stays honest.

## What can move further down the model ladder

**Down to the script (no model at all):** formatting, lint autofix, scope
enforcement, baseline capture, the red-test proof, worktree hygiene. Items
1–4 above are all of this kind, and together they are most of what the
supervisor spent tool calls on.

**Down to the delegate, safely:** writing the *tests* for a phase whose
implementation already landed, given an explicit list of cases. It wrote
correct table tests every round when the cases were enumerated for it. It did
not invent cases worth having when they were not.

**Must stay at the top tier:** the phase spec itself, the frozen design
decisions, commit prose, and any judgement about whether a green diff is
actually right. Phase 03's defect is the proof — the code was complete, the
tests passed, the lint was clean, and it was still wrong in a way only
reading the control flow against the phase's *purpose* would reveal.

**Should not move down: the architect's own review of the landed diff.** Every
one of the three structural-residue fixes came from that read, as did the
pre-existing `Enqueue`/`Close` panic — a latent process-killing bug found not
by any test or delegate but by hand-tracing an in-flight counter for balance.

## Working around big-pickle's context ceiling

What demonstrably worked, and should be codified as rules rather than advice:

- **Name files *and line ranges* to read** ("`actions.go`, lines 320..409
  only"). Every one-round success had them. Never say "read the package".
- **Say what not to read, explicitly.** Reading budget is the scarcest
  resource it has.
- **One file written, at most three read.** Phase 04 wrote two files and ran
  530s against a 600s timeout — the near miss confirms the rule rather than
  refuting it.
- **State the invariant, not just the change.** "The no-policy path must be
  byte-for-byte unchanged" was repeated in four specs and held in all four.
- **A correction round is a new, narrow file.** Phase 03's r2 spec addressed
  exactly one missing line and produced exactly one line in 58 seconds.
  Re-running the original spec would have rewritten the whole thing worse.
